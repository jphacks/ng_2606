# 写真の読み取り：答えの形と指示文

B の Step 6 で作った、Claude への指示文と答えの JSON の形です（00_overview.md 9.4）。A のサーバー（A Step 24）と B の StageReader（B Step 7）が、同じファイルを使います。

| ファイル | 中身 | 使う人 |
| --- | --- | --- |
| Assets/_Project/Stage/Llm/scan_prompt.md | Claude への指示文 | サーバー（system か、写真と一緒の文として渡す） |
| Assets/_Project/Stage/Llm/scan_result.schema.json | 答えの JSON スキーマ | サーバー（構造化出力 output_config.format に渡す）、B（形の確認） |

## 答えの項目

2026-10-24：A4 の紙がなくても箱を作る決まりに変えた。紙があると正確になる。紙がないときは、Claude が身の回りの物の大きさから推定し、何を基準にしたかを scaleReference に書く。

| 項目 | 型 | 単位 | 意味 | 範囲（B が確かめる） |
| --- | --- | --- | --- | --- |
| paperFound | true / false | ― | 基準の紙が写っていて、長さの基準に使えたか | false でも箱は作る（大きさは推定） |
| scaleReference | 文字列 | ― | 長さの基準に使った物 | ― |
| desk | 幅と奥行き、または null | cm | 机の天面の大きさ。紙があり、机の端が写っているときだけ。それ以外は null | 20〜300 |
| deskInPhoto1 | 四隅（x0,y0 … x3,y3） | 割合 | 1枚目（真上）の写真の中の、机の四隅。3D のステージに机の絵を貼るため。分からなければ 8つとも 0 | 0〜1（外れたら使わない） |
| blocks | 物の一覧 | ― | 机の上の物。紙は入れない | 0〜100件 |
| notes | 文字列 | ― | 人が読むメモ | ― |

blocks の1件：

| 項目 | 単位 | 意味 | 範囲（B が確かめる） |
| --- | --- | --- | --- |
| label | ― | 何の物か | ― |
| centerXCm、centerZCm | cm | 上から見た中心。原点（紙の左手前の角。紙がなければ物を全部囲む長方形の左手前の角）から右（X）と奥（Z）へ | 机の中 |
| widthCm、depthCm | cm | 上から見た長い方の辺、短い方の辺 | 1〜60 |
| heightCm | cm | 机の天面からこの物の上面まで（積んだ物は机から） | 0.5〜40 |
| yawDegrees | 度 | 長い方の辺が +X から反時計回りに何度か | 0 以上 180 未満 |
| confidence | ― | 自信の度合い | 0〜1 |
| topFaceInPhoto1 | 割合 | 1枚目（真上）の写真の中の、この物の上面の四隅（x0,y0 … x3,y3）。写真の左上が (0, 0)、右下が (1, 1)。ぐるっと一周する順。3D のステージに、本物の写真を貼るため。分からなければ 8つとも 0 | 0〜1（外れたら使わない） |

**写真を貼る（2026-10-24 に足した）：** `deskInPhoto1` と `topFaceInPhoto1` は、3D のステージに本物の写真を貼るための位置。B の `StageReaderCore` が読み、`StagePhotoRegions` に入れる。使えない位置（8つとも 0、範囲の外、面積がほぼ 0）は、その箱には写真を貼らない。貼るのは、合流のつなぎ（`Merge/StagePhotoTexturer`）。位置は、LLM が写真を見て答える値なので、ずれることがある。

構造化出力のスキーマには、数の範囲（minimum など）を書けません。範囲は説明文に書き、B の Step 7 で確かめて、外れた物は箱にしません。

## ステージ座標への直し方（B Step 7）

- cm を m にする（100 で割る）
- 机の中心が原点になるように、`x = centerXCm/100 − 机の幅/2`、`z = centerZCm/100 − 机の奥行き/2` にする
- 箱の大きさ：`size = [widthCm, heightCm, depthCm] / 100`、中心の高さは `heightCm/100/2`
- 回転：答えは「上から見て反時計回り」。Unity の `Quaternion.Euler(0, θ, 0)` は上から見て時計回りなので、`θ = (360 − yawDegrees) % 360`
- desk が null なら、物を囲む長方形に 10cm の余白を付けた範囲を机にする
- 机の奥行きの方が長いときも、90度は回さない（B Step 7 で決めた）。回すと、3D画面の向きが、子どもが机を見ている向きと変わってしまうため。00_overview.md 3.1 の「長い辺を X」は、写真の方式では使わない
- 中心が机の外の物、範囲を外れた物、高さ 0.5cm 未満の物は箱にしない。数はログに残す

{"paperFound": true, "scaleReference": "", "desk": {"widthCm": 0, "depthCm": 0}, "blocks": [{"label": "", "centerXCm": 0, "centerZCm": 0, "widthCm": 0, "depthCm": 0, "heightCm": 0, "yawDegrees": 0, "confidence": 0}], "notes": ""}

## 試した結果

### 2026-10-24 その1：机の上の箱3つ（A4 の紙なし）

- 写真：斜めから2枚（真上の写真はなし）。A4 の紙は置いていない
- 読み取ったのは、この会話の Claude（指示文 scan_prompt.md に沿って）。サーバーはまだない
- 紙がないため、指示文どおりなら paperFound は false で箱を作らない。試しなので、プロッキー（三菱鉛筆）の箱の横を約 19.5cm として長さを推定した

| 物 | 推定の大きさ（幅 × 奥行き × 高さ cm） | 自信 |
| --- | --- | --- |
| プロッキーの箱 | 19.5 × 13.0 × 2.0 | 0.6 |
| 細長い段ボール箱 | 30.0 × 11.0 × 4.0 | 0.5 |
| 大きな段ボール箱 | 25.0 × 24.0 × 24.0 | 0.4 |

- 並び：手前にプロッキーの箱、その後ろにくっついて細長い箱、4cm くらいあけて奥に大きな箱
- この答えから作ったステージ：Assets/StreamingAssets/Stages/photo-test-01/stage.json（机は物を囲む長方形に 10cm の余白。机の奥行きの方が長いが、90度回していない）
- 段差：机 → プロッキーの箱 2cm（跳べる）→ 細長い箱 +2cm（跳べる）→ 大きな箱 +20cm（壁）
- 分かったこと：物の数と並び方は読める。長さの基準がないと、大きさは市販品の推定に頼る。真上の写真がないと、奥の物の奥行きが読みにくい

### 2026-10-24 その2：同じ写真を、サーバーから本物の Claude に送った

- サーバー（Server/）から `claude-opus-5-5` に送った。写真は縮めずに送った（4284 × 5712）

- 答え：`paperFound: false`、`blocks: []`。指示文のとおり、A4 の紙がないので箱を作らなかった

- 分かったこと：指示文の「紙がなければ作らない」はきちんと守られる。写真を A の Step 22 のとおり長い辺 1568px に縮めれば、入力のトークンはもっと減る見込み
