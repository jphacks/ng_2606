# ramp-support

> **実装が先行した記録。** 実装を先に進めてから、この仕様を書いた（2026-11-03）。
> 範囲は、ユーザーが「斜めの坂にしたい」「B（本物の坂）にする」と指示して決めた。
> 共通のデータ（BoxData）への項目の追加は、ユーザーの承認を得た。
> 仕様を実装に合わせて曲げず、ずれがあれば実装の側を直す。

## 何を作るか

斜めに立てかけた板などを、ステージの中でも斜めの坂（くさび形）にする。
読み取り（Claude の答え）から、ステージの組み立て、見た目、遊びの判定まで通す。

## なぜ必要か

青い折り紙を貼った板を、箱に立てかけて撮っても、ステージでは水平な箱になっていた。
実物の形（斜め）がステージに出ないので、「机の上のものがそのままステージになる」という
アプリの狙いと合わない。

## 完成の条件

- [x] REQ-1: 読み取りの答えの形に、坂かどうか（isRamp）とのぼる向き（uphillYawDegrees）が入る。サーバーは、指示文とスキーマの最新（ng_2606-photo 側）を読む
- [x] REQ-2: isRamp が true の物は、くさび形になる。低い端が机の高さ 0、高い端が heightCm。のぼる向きは、答えの向きに最も近い板の軸（長い辺・短い辺、どちら向きでも）にそろう
- [x] REQ-3: 坂の当たり判定も、くさび形になる。キャラは、傾き 45 度までの坂を歩いてのぼれる
- [ ] REQ-9（2026-11-03 追加）: 水でない坂（色の無い坂、炎・回復の坂）で、傾きが 45 度より急なものは、歩いてはのぼれないが、ジャンプを使えばのぼれる（80 度まで。80 度より急な坂は、箱の壁と同じ）
- [ ] REQ-10（2026-11-03 追加、同日に変更）: 水の坂（青い折り紙）は、流れの向きを、置いたあとに選べる（たしかめの画面のふだんの状態で、水の箱・水の坂の上に「ながれの むき」のボタンが出る。「なおす」を開かなくてよい）。向きを選んでいなければ、坂の下へ流れる。坂の上の流れは、歩く速さより強く、ジャンプで浮いている間も流す。下り向きなら、のぼれず下りることだけできる。上り向きなら、流れに乗ってのぼれる
- [x] REQ-4: 坂の斜めの面に、撮影の写真としかけ（水・炎・回復）の模様が貼られる。しかけの効き目は、斜めの面の上にいるときに働く。水は、向きを選んでいなければ、坂の下へ流れる
- [ ] REQ-5: 坂の上に、スタートとゴールを置ける（面の傾き 45 度まで）。届くかの調べでは、傾き 80 度までの水でない坂は、のぼれるものとして扱う（45 度まで歩いて、それより急ならジャンプで）。80 度より急な坂は、箱の壁と同じ扱い。水の坂は、下り向きなら同じ高さか高い所からの下りだけ通れ、上り向き・横向きなら、水でない坂と同じくのぼれる
- [x] REQ-6: 保存したステージに、坂が残る。坂の項目が無い古い保存データは、ふつうの箱として読める
- [x] REQ-7: 坂には、段の印（とぶ・ばつ）を出さない。高さをそろえる処理と、すき間をふさぐ処理は、坂に働かない
- [x] REQ-8: 坂でない箱の動きは、これまでと変わらない（EditMode テストが全部通る）

## やらないこと

- 「なおす」の画面で、坂の傾きや向きを直すこと
- 坂の下の空間への入り込み（くさび形の中は、中身が詰まったものとして扱う）
- 傾き 45 度を超える坂を、歩いてのぼること（ジャンプでのぼる。REQ-9）
- 傾きの角度そのものを、データに持つこと（高さと、のぼる向きの長さで決まる）

## 未決の判断

- REQ-1〜8 は、2026-11-03 に、実機（iPhone）で青い板を立てかけて生成し、ユーザーが「成功」と確認した（まとめての確認）
- REQ-9・10 と、変えた REQ-5 は、ユーザーの指示（「45 度より急な普通の坂はジャンプで登れる。水色（下向き）は登れず、下りることしかできない」、続けて「水の流れる方向は設置後に設定できるようにして、逆に上にも登れるようにして」）で追加・変更した。実機での確認はまだ
- 共通のデータへ足した項目は、`ramp`（true / false）の 1 つだけ。向きは既存の yawDegrees、傾きは高さと長さから決まる
