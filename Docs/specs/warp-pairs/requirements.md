# warp-pairs

## 何を作るか

ピンク（ワープ）の箱を、「どこかランダムな所へ飛ぶ」から、「つないだピンクの箱どうしを行き来する」に変える（2026-11-07 の依頼）。
作る人が、たしかめの画面で、どのピンクとどのピンクをつなぐかを決める。

## なぜ必要か

いまのワープは、飛ぶ先がランダムなので、コースの作り手が狙った道を作れない。マリオの土管のように、
入口と出口を決めて、コースの一部として使えるようにしたい。

## 完成の条件

- [ ] REQ-1: ピンクの箱は、ほかのピンクの箱 1 つと「つながる」。つながった 2 つの箱は、どちらに乗っても、もう片方の箱の上へ飛ぶ（行き来できる）
- [ ] REQ-2: ピンクの箱が 1 つだけのときは、ワープしない（ふつうの箱と同じ）。たしかめの画面で「ワープは ピンクが 2こ いるよ」と伝える。遊ぶことはできる
- [ ] REQ-3: 撮ってピンクの箱が見つかったら、近い順に 2 つずつ、自動でつなぐ（数が奇数なら、1 つは余る）
- [ ] REQ-4: たしかめの画面で、ピンクの箱の上に、つながりのボタン（例：「1 ⇄ 2」）が出る。押すたびに、つながる相手が、次のピンクの箱に変わる。前の相手と、新しい相手の前の相手は、余った物どうしで、つなぎ直す
- [ ] REQ-5: 飛んだ先は、つながった箱の上面の真ん中（キャラが入れなければ、上面の中の空いている所）。飛んだあとの 3 秒は、続けて飛ばない（いまと同じ）
- [ ] REQ-6: つながりは、保存したステージに残る（みんなの ステージは 2026-11-07 に消した）。古い保存データ（つながりの項目が無い）は、読み込んだときに、近い順に自動でつなぐ
- [ ] REQ-7: つなぎ方の決まり（自動でつなぐ、押して変える、行き来の対称）は、画面に触れない計算として分け、EditMode テストで確かめる

## やらないこと

- ピンク以外の箱や、机の上を、飛ぶ先にすること
- 片道のワープ
- 遊ぶ画面で、つながりの線を描くこと（たしかめの画面のボタンの番号で見せる）

## 未決の判断

なし（2026-11-07 にユーザーが決めた）
- ピンクが 1 つだけのときは、ワープしない（遊ぶことはできる）
- 飛ぶ先は、ほかのピンクの箱
- 決め方は、箱の上のボタン（押すたびに次のピンクへ）
- 行き来できる（2 つずつの組）
- 共通のデータ（BoxData）に、つながる相手の箱の id（warpTo）を 1 つ足す。共通コードの変更なので、この仕様の承認を、その許可とする
