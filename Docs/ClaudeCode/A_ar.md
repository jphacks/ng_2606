# A：AR・空間認識 Claude Code 作業手順

先に Docs/ClaudeCode/00_overview.md を読んでください。このファイルの名前（クラス、イベント、依頼）は、すべて 00_overview.md の4章の共通コードに合わせています。A は全体の Step 1〜4（プロジェクトの土台）も担当します。

## Aの仕事

子どもが机の上に並べた物を、スマホで撮って読み取る「土台」を作ります。カメラで机の写真を2枚撮り、明るさとぶれを確かめて、サーバーに送ります。サーバーは写真を Claude に渡し、物ごとの位置と大きさの答え（JSON）を返します。その答えを B に渡すまでと、サーバー自体、iPhone へのビルドが A の担当です（00_overview.md 9章）。

> 2026-10-24：読み取りの方式を「写真と Claude」に変えた（00_overview.md 9章）。面の検出の Step（6〜13、19）は使わない。写真の方式の Step を 21〜25 として足した。同じ日から、A と B は同じ人が担当する。

完成の姿：子どもが机を2枚撮ると、30秒以内に答えが B に届く。写真が暗い・ぶれているときは、送る前に撮り直しを頼める。通信が失敗しても、アプリが止まらない。

## P0

### Step 1：テスト用シーンと初ビルド【CC＋人】

- 目的：カメラ映像が映るだけの AR アプリが iPhone で動くことを確かめる
- 作るもの：エディタ用スクリプト AR/Editor/CreateTestScene（メニュー「DeskStage/A/テスト用シーンを作る」）、Docs/BuildGuide.md
- やること
  1. 【CC】メニューを実行すると Scenes/Test_A.unity を作り、AR Session と XR Origin (Mobile AR) を置き、XR Origin の前方50cmに一辺5cmの立方体を置くエディタ用スクリプトを作る（初めからある Main Camera は消す）
  2. 【人】メニューを実行し、Build Profiles で Test_A をシーン一覧に入れ、Development Build にチェックを入れてビルドする。書き出し先はプロジェクトの外のフォルダ
  3. 【人】Xcode で Unity-iPhone.xcodeproj を開き、Signing & Capabilities で Automatically manage signing と自分の Personal Team を選び、iPhone で実行する（初回はデベロッパモードと、設定の「VPNとデバイス管理」で信頼が必要）
  4. 【CC】人から聞いた手順とつまずいた点を、Docs/BuildGuide.md にまとめる。無料の Apple ID のアプリは7日で開けなくなることも書く
- 確認：iPhone でカメラ映像が画面いっぱいに映り、スマホを動かしても立方体が空中の同じ場所に留まる。BuildGuide.md がある

### Step 2：スキャンの設定アセット【CC】

- 目的：仮の値を1か所にまとめ、検証の結果で変えやすくする
- 作るもの：ScriptableObject の ScanSettings と、その初期値のアセット AR/Settings/ScanSettings.asset（アセットはエディタ用スクリプトで作る）
- 持つ値と初期値

| 値 | 初期値 | 意味 |
| --- | --- | --- |
| 机の外として捨てる距離 | 0.05m | 机の長方形より外にある面を捨てる |
| 机の一部として捨てる高さ | 0.008m | これより低い面は机の一部（Cの決まりと同じ） |
| 高すぎる面 | 0.40m | これより高い面は捨てる |
| 小さすぎる面積 | 0.0016㎡ | 16cm²未満の面は捨てる |
| 高さをなめらかにする時間 | 1秒 | 高さの値を新しい値へ寄せる速さ |
| 同じ物とみなす高さの差 | 0.01m | まとめる条件 |
| 同じ物とみなすすき間 | 0.01m | まとめる条件 |
| ふちを広げる量 | 0.005m | ARKit の面が実物より小さい分を補う |
| 落ち着くまで待つ時間 | 1秒 | 形が大きく変わらなくなってから一覧に出す |
| 知らせの最小間隔 | 0.25秒 | SurfacesChanged を1秒に4回まで |
| Lost とみなす再推定の時間 | 3秒 | 位置の再推定がこれ以上続いたら Lost |

- 確認：アセットが作られ、Inspector で値が見える

### Step 3：検証用の表示と記録（PlaneProbe）【CC】

- 目的：P0 の検証で、どの物の上面が、何秒で、どの高さで見つかるかを記録できるようにする
- 作るもの：AR/Debug/PlaneProbe、Test_A に置くエディタ用スクリプトの追加
- やること
  1. XR Origin に AR Plane Manager（探す向きは Horizontal）と AR Raycast Manager を付ける（エディタ用スクリプトで）
  2. 見つかった面ごとに、高さで色を変えた半透明の板を表示する（低い＝青、高い＝赤）
  3. 面の中心に「高さ（cm）」と「大きさ（cm×cm）」の文字を出す。高さは、いちばん低い大きな面（ふつうは机）からの差
  4. 面が初めて見つかった時刻（スキャン開始からの秒数）を覚える
  5. 画面をタップしたら、AR Raycast Manager でタップした先の点（面と特徴点）を調べ、その高さを画面に出す
  6. 画面の「記録」ボタンで、その時点の面の一覧（番号、高さ、大きさ、見つかった秒数）とタップの記録を、アプリの保存場所にテキスト（CSV）で書き出す
  7. 「リセット」ボタンで AR の記録を消してやり直せるようにする（Step 12 の試し）
- 確認：【人】実機で机と箱1つを映すと、2枚の面が別の色で出て、高さの差が表示される。記録ボタンで CSV ができ、Mac につないで取り出せる

### Step 4：平らな面の検出の実機検証【人】（B と一緒に）

- 目的：子どもが並べそうな物で、iPhone 17 がどこまで見つけられるかを確かめる。この結果で方式の成否が決まる
- Claude Code がすること：人に下の手順を伝え、結果の CSV を Docs/PlaneCheck.md の表にまとめるのを手伝う
- 検証する物（B が用意する）：小さい段ボール箱、大きい段ボール箱、四角い積み木、絵本と文庫本、ティッシュの箱、無地の折り紙を貼った箱、見つけにくそうな物（白い無地の箱、黒い箱、つやのある箱）
- やること（各物3回ずつ）
  1. スキャン開始から上面が見つかるまでの秒数（60秒で見つからなければ「なし」）
  2. 表示された高さと定規の高さの差
  3. 表示された面の大きさと、実物の上面の大きさの比
  4. 物の上面をタップしたときの点の高さ（補助で箱を足すときの手がかりに使えるか）
  5. 子どもが作りそうなコース（物5〜8個、積んだ所1か所以上）で、全部の上面が見つかるまでの秒数
  6. 物を2つ動かして「リセット」してから、新しい並べ方が全部見つかるまでの秒数
- 合格ライン（仮）

| 項目 | 合格ライン |
| --- | --- |
| 段ボール箱、本、ティッシュの箱 | 30秒以内に、3回中3回 |
| 積み木 | 3回中2回以上 |
| 高さの差 | すべての物で±1cm以内 |
| 見つけにくそうな物 | 記録だけ |
| コース全体 | 90秒以内 |
| もういちど（リセット後） | 60秒以内 |
| 机の天面 | 10秒以内 |

- 確認：Docs/PlaneCheck.md の表がすべて埋まり、合格ラインとの合否が書かれている

### Step 5：判定会議【人】

- 目的：検証の結果から、並べる物の決め方を決める
- 案

| 結果 | 案 |
| --- | --- |
| すべて合格 | 案A：家にある物を自由に並べてよい |
| 小さい物や一部の物が見つかりにくい | 案B：並べる物の決まりを画面と紙で伝える |
| 無地や色の濃い物が見つかりにくい | 案C：上面にのせる「もようシート」を用意する |
| どの物も遅い・不安定 | 案D：見つかりやすい箱のセット（ステージキット）を並べる |

- Claude Code がすること：決まった案と、ScanSettings の値を変えるべき所（ふちを広げる量、小さすぎる面積など）を人と確かめ、設定アセットを直す
- 確認：決まった案が設計書に記録され、ScanSettings に検証の結果が反映されている

## M1

### Step 6：面の見張り（PlaneWatcher）【CC】

- 目的：ARKit の面のうち、上向きの水平な面だけを覚えておく
- やること
  1. AR Plane Manager の「面が増えた・変わった・消えた」の知らせを受ける（AR Foundation 6 では trackables changed という知らせ）
  2. 向きが上向きの水平（HorizontalUp）の面だけを使う
  3. 面ごとに、ARKit の番号、中心、高さ、境界の点の並び（世界座標）、最後に変わった時刻を覚える
  4. 消えた面（別の面に飲み込まれた面を含む）は外す
  5. 覚えている面の一覧を、他の部品（DeskFrame、SurfaceStabilizer）が読めるようにする
- 確認：【人】実機で机と箱2つを映すと面が3枚覚えられ、映さなくなっても消えない（PlaneProbe の表示か、デバッグのログで確かめる）

### Step 7：長方形の当てはめ（共通の計算）【CC】

- 目的：「点の並びを囲む、いちばん面積の小さい長方形」を求める計算を、A と B の両方で使えるようにする
- 作るもの：Shared/Geometry/RectFit（普通のクラス）と EditMode テスト
- やること
  1. 共通コードへの追加なので、00_overview.md の 2.2 のとおり、追加の案を書いて人に確認してもらう
  2. 入力は XZ 平面の点の並び、出力は中心、幅、奥行き、上から見た回転（度）。長い方の辺を幅にする
  3. 求め方は「凸包を作り、凸包の各辺に沿った長方形のうち面積が最小のもの」
  4. テスト：正方形、回した長方形、点が3つだけ、点が1つだけ（エラーにせず大きさ0）、点がばらついた形
- 確認：テストがすべて通る

### Step 8：机の決定とステージ座標（DeskFrame）【CC＋人】

- 目的：子どもがタップした面を机に決め、その上にステージ座標（StageRoot）を置く
- やること
  1. スキャン状態を FindingDesk にする
  2. UiRequests の SetDesk（画面のタップ位置）を受けたら、AR Raycast Manager でタップした先の面を調べる。当たった面を机の面にする。当たらなければ何もしない
  3. 机の面の境界の点に RectFit を使い、長方形を求める
  4. 長方形の中心で、机の面の高さに StageRoot を置き、向きを長方形の辺に合わせる。StageRoot に AR Anchor を付ける
  5. ScanContext.DeskSize を書き、StageContext.StageRoot を登録し、DeskDecided を出し、状態を Scanning にする
  6. スキャン中も机の面は広がるので、DeskSize は更新し続ける。ただし原点と向きは変えない（箱がずれないように）
  7. 机が決まった後の SetDesk は無視する（決め直しは Rescan で）
- 確認：【人】実機で机をタップすると、確認用の一辺5cmの立方体が机の中心に、机の辺と平行に置かれる

### Step 9：スキャン状態の報告（ScanStatusReporter）【CC＋人】

- 目的：AR の状態を、子ども向けの案内を出すための共通の状態に置き換える
- やること：毎フレーム、AR Session の状態と追跡できない理由を調べ、下の表で置き換える。変わったときだけ ScanStatusChanged を出す

| AR の状態 | 理由 | スキャン状態 |
| --- | --- | --- |
| AR を使っていない | ― | NotStarted |
| 準備中 | ― | Starting |
| 追跡中 | なし | 机が決まる前は FindingDesk、後は Scanning |
| 追跡中または初期化中 | 暗い | Limited（Dark） |
| 追跡中または初期化中 | 動きが速すぎる | Limited（FastMotion） |
| 追跡中または初期化中 | 模様が少ない | Limited（FewFeatures） |
| 位置の再推定中が3秒以上 | ― | Lost |
| FinishScan の後 | ― | Finished |

- 確認：【人】カメラを手で覆う、スマホを素早く振る、白い壁だけを映す、でそれぞれ正しい理由の Limited になる

### Step 10：スキャンの開始と終わり（ScanSession）【CC】

- 目的：D の依頼で AR を始め、止める
- やること
  1. StartScan を受けたら AR Session と AR Plane Manager を動かし、状態を Starting にする
  2. FinishScan を受けたら AR Plane Manager を止める（見つけた面は残す）。状態を Finished にする。たしかめ画面でカメラ映像を使うので AR Session は止めない
  3. StageContext.Mode が Play になったら（保存して遊ぶとき）、AR Session を止め、状態を NotStarted にする
  4. 【未決】遊ぶ画面の背景をカメラ映像にすると決まった場合は、3 を変える。決まるまでは完全な3D画面として作る
- 確認：【人】StartScan → 机をタップ → FinishScan → Mode を Play、の順で、状態が Starting → FindingDesk → Scanning → Finished → NotStarted と変わる（D の画面がまだなければ、Test_A に仮のボタンを置いて確かめる）

### Step 11：面の安定化（SurfaceStabilizer）【CC＋人】

- 目的：ARKit の面を、B が箱を作りやすい「整えた上面の一覧」にする
- 作るもの：計算の部分（普通のクラス）と、それを毎フレーム動かす部品。EditMode テスト
- やること（値はすべて ScanSettings から読む）
  1. 机が決まるまでは何もしない
  2. 面の点をステージ座標に直す
  3. 机の長方形より外（0.05m より外）の面、机より低い面を捨てる
  4. 机からの高さが 0.008m 未満の面と、0.40m を超える面を捨てる
  5. 上から見た面積が小さすぎる面を捨てる
  6. 面ごとに高さの値をなめらかにする（1秒かけて新しい値に寄せる）。1mm 単位に丸める
  7. 高さの差が 0.01m 以内で、上から見て重なるか、すき間が 0.01m 以内の面は1つにまとめる。高さは面積の大きい方に合わせる。まとめた面には新しい番号を付け、元の番号を覚える
  8. 各辺を「ふちを広げる量」だけ外へ広げる
  9. 見つかってから1秒以上、形が大きく変わらなかった面だけを一覧に出す
  10. 一覧が変わったら ScanContext.Surfaces を書き換え、SurfacesChanged を出す（最小間隔 0.25 秒）
  11. テスト：本2冊を並べた形は2つ、重ねた形は上の1つ、同じ箱の面が2枚に分かれた形は1つ、低いノートは出ない、机の外の面は出ない
- 確認：テストがすべて通る。【人】実機で、本2冊が別の上面になり、同じ箱の面が1枚になり、1分間映し続けても高さの揺れが±3mm未満

### Step 12：もういちどスキャン【CC＋人】

- 目的：子どもが物を並べ直したときに、前の並べ方の面を残さず、机から探し直す
- やること

  2. PlaneWatcher と SurfaceStabilizer の記録、ScanContext.Surfaces を空にし、SurfacesChanged を出す
  3. StageRoot を消し、状態を FindingDesk に戻す（机のタップからやり直し）
- 確認：【人】箱を2つ並べてスキャンした後、1つをどけて Rescan すると、どけた箱の面が出てこない。60秒以内に新しい並べ方の上面が全部見つかる

### Step 13：B と高さの誤差を確かめる【人】

- 目的：箱の高さが実物と±1cm以内かを確かめ、ずれていれば原因を切り分ける
- Claude Code がすること：B の記録（Docs/ScanAccuracy.md）を読み、下の表で原因の候補と、変える設定の案を出す

| 見え方 | 疑う原因 | 変える案 |
| --- | --- | --- |
| どの物も同じくらい高い・低い | 机の面の高さの推定 | 机の面の高さを、決めた時点の値で止める |
| 低い物ほど誤差が大きい | 机の面と物の面が混ざる | 机の一部として捨てる高さを見直す |
| 模様のない物だけずれる | 手がかり不足 | 案C（もようシート）を検討。補助の案内 |
| 時間がたつとずれる | AR の空間のずれ | 見つかってから10秒後の高さで止める案を試す |

- 確認：誤差の原因と対策が Docs/ScanAccuracy.md に書かれている

## 写真の方式（2026-10-24 から）

00_overview.md 9章の流れを作ります。A と B は同じ人が担当しますが、A と B の部品の間は、これまでどおり共通コードだけでやり取りします。

### Step 21：共通コードに足す【CC＋人】

- 目的：写真の方式で使う知らせと依頼を、全員が使えるようにする
- やること
  1. 【CC】00_overview.md 9.3 のとおり、ScanContext に `ScanResultReceived`（string）と `RaiseScanResultReceived`、`CameraPreview`（Texture）を、UiRequests に `TakePhoto` と `RequestTakePhoto` を足す
  2. 【CC】Docs/SharedCode.md に足した物を書く
  3. 【人】共通コードの変更なので、C と D に見てもらってから合流する（2.2）
- 確認：コンパイルエラーがない。EditMode テストがすべて通る

### Step 22：カメラと撮影（PhotoCapture）【CC＋人】

- 目的：撮影画面のボタンで、机の写真を2枚撮る
- やること
  1. StartScan を受けたら、背面カメラを WebCamTexture で開き、ScanContext.CameraPreview に入れる。スキャンの状態を FindingDesk にする
  2. TakePhoto を受けたら、今の画面を写真にする。1枚目は真上、2枚目は斜め。1枚目のあとは状態を Scanning にする
  3. 写真は JPEG（品質 85）にし、長い辺が 1568px より大きければ縮める（大きすぎると送るのに時間がかかるため）
  4. 2枚そろったら、Step 23 の確認をしてから Step 25 で送る。FinishScan ではなく、2枚目を撮ったら自動で送る
  5. 前の方式の ScanSession（Step 10）と DeskFrame（Step 8）は、写真の方式のシーンには置かない
  6. 数値（写真の品質、長い辺の上限など）は ScanSettings に足す
- 確認：【人】PC のカメラ（Unity エディタ）と実機の両方で、2枚撮れて、写真がログの場所に保存される（開発中だけ）

### Step 23：写真の確認（PhotoCheck）【CC】

- 目的：使えない写真を送らない（時間と API の料金のむだを防ぐ）
- 作るもの：計算の部分（普通のクラス）と EditMode テスト
- やること
  1. 明るさ：写真の平均の明るさが低すぎたら、状態を Limited、理由を Dark にする
  2. ぶれ：写真のくっきりさ（明るさの変化の大きさ）が低すぎたら、状態を Limited、理由を FastMotion にする
  3. どちらかに当てはまったら送らず、その写真だけ撮り直してもらう（D が「もういちど とってね」と出す）
  4. しきい値は ScanSettings に入れる。仮の値は、テスト用の写真で決める
  5. テスト：真っ黒の画像は暗い、ぼかした画像はぶれ、ふつうの写真は通る
- 確認：テストが通る

### Step 24：サーバー（Server/）【CC＋人】

- 目的：API キーを iPhone に置かずに、写真を Claude に渡す
- 作るもの：リポジトリの一番上の Server/ に、Python の小さなサーバー。Unity の外なので .meta はない
- やること
  1. 【人】使うもの（Python、Web サーバーのライブラリ、Anthropic の Python SDK）を入れてよいか、確認する（2.2 の新しいパッケージ）
  2. 【CC】POST /scan：2枚の写真（真上と斜め）を受け取り、Claude（モデル ID `claude-opus-5-5`）に画像と指示文（B の Stage/Llm/scan_prompt.md）を渡す。答えの形は構造化出力（output_config.format）に B のスキーマ（Stage/Llm/scan_result.schema.json）を渡して固定する
  3. 【CC】Claude が答えを断ったとき（stop_reason が refusal）に備え、サーバー側の代わりのモデルの設定（fallbacks）を入れる。入れたことを人に伝える
  4. 【CC】API キーは環境変数 ANTHROPIC_API_KEY から読む。リポジトリにもアプリにも書かない。.env は .gitignore に入れる
  5. 【CC】アプリからの合言葉（ヘッダー）がないリクエストは断る。1日の回数の上限を超えたら断る（00_overview.md 8章）
  6. 【CC】写真は保存しない。ログにも写真を書かない（00_overview.md 9.5）
  7. 【CC】Server/README.md に、PC での動かし方と、置き場所（00_overview.md 8章）へのデプロイの仕方を書く
- 確認：【人】PC でサーバーを動かし、お手本ステージの2枚の写真を送ると、スキーマどおりの JSON が返る。合言葉なしでは断られる

### Step 25：サーバーとの送受信と、もういちど撮る（ScanClient）【CC＋人】

- 目的：アプリから写真を送り、答えを B に渡す
- やること
  1. 2枚の写真を UnityWebRequest で POST /scan に送る。サーバーの URL と合言葉は ScanSettings に入れる（合言葉はリポジトリに入れない設定ファイルから読む）
  2. 待っている間は状態を Scanning のままにする。90 秒で打ち切る
  3. 答えが届いたら、ScanContext.RaiseScanResultReceived に JSON を渡し、状態を Finished にする
  4. 通信の失敗、サーバーの断り、答えの形が違うときは、状態を Lost にして、理由をログに残す
  5. Rescan を受けたら、撮った写真を捨てて、Step 22 の1 からやり直す（B は箱を消す。B の Step 8）
- 確認：【人】実機で2枚撮ると、30秒以内に B の箱が出る。機内モードで撮ると Lost になり、アプリが止まらない

## 困ったとき

| 起きていること | よくある原因 | 直し方 |
| --- | --- | --- |
| 画面が真っ黒 | AR Background Renderer Feature がない、カメラの許可がない | 全体 Step 1 の7を確かめる。iPhone の設定でカメラをオン |
| 起動直後に落ちる | Camera Usage Description が空 | Player の設定に文章を入れる |
| 昨日まで動いたアプリが開かない | 無料の Apple ID の期限（7日） | Xcode から入れ直す |
| 面が1枚も見つからない | 探す向きが未設定、暗い | Plane Manager の探す向きを Horizontal に。明るくする |
| 机の天面が広がらない | 机の上に物が多い | 物の少ない側から映す、ゆっくり1周する |
| 1つの物に面が2つ出る | まとめる条件が厳しい | ScanSettings の「同じ物とみなすすき間」を少し広げる |
| 隣の2つの物がくっつく | まとめる条件がゆるい | 同じ値を狭める |
| 並べ直したのに前の面が出る | AR の記録をリセットしていない | Step 12 の1を確かめる |
| 箱全体が少しずつずれる | StageRoot に AR Anchor がない、原点を動かしている | Step 8 の4と6を確かめる |
| エディタで AR が動かない | AR は実機でしか動かない | XR Simulation を使う。ゲームや箱の確認は B のお手本ステージで |
