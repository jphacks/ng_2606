# C：キャラ・ゲームプレイ Claude Code 作業手順

先に Docs/ClaudeCode/00_overview.md を読んでください。このファイルの名前（クラス、イベント、依頼）は、すべて 00_overview.md の4章の共通コードに合わせています。

## Cの仕事

身長3cmのキャラが、子どもが並べてスキャンした「箱でできたステージ」の上を気持ちよく走り、スタートからゴールまでをゲームとして成り立たせます。箱の高さの決まり（どの高さならジャンプで登れるか）を最初に決めて、B と D に渡すのも C の大事な仕事です。この決まりは、子どもが現実の物を並べるときの目安（たかさものさし）にもなります。

完成の姿：子どもが並べてスキャンしたステージで、説明なしにゴールまで遊べる。箱の上で引っかからず、すり抜けず、落ちてもすぐに戻れる。子どもが本物の物を見ながら、スタートとゴールを置ける。

## P0

### Step 1：箱の高さの決まり【CC】

- 目的：ステージの遊びやすさを決める基準を、最初に全員で共有する
- やること
  1. Docs/StepRules.md に下の表を書く。4.5cm はジャンプの高さ 5cm から、キャラの足が段の角に引っかからないための余裕 0.5cm を引いた値であることも書く
  2. 箱の高さの下限 0.5cm、すき間は 1.6cm（キャラの太さ）以上か 0、も書く（B の箱づくりの決まりと同じ）
  3. 計算の StepRules を作る（高さの差を渡すと Walk、Jump、Wall を返す。境目の値は CharacterSettings から読む）。EditMode テストで境目を確かめる

| 隣の面との高さの差 | 扱い | 子どもへの見せ方 |
| --- | --- | --- |
| 0.8cm未満 | Walk：歩いて登れる | 何も出さない |
| 0.8〜4.5cm | Jump：ジャンプで登れる | 緑の印 |
| 4.5cmを超える | Wall：登れない壁 | 赤の印。となりに低い物を置けば登れる |

- 確認：テストが通る。B と D が読んで使えると言った（人）

### Step 2：キャラの設定アセット【CC】

- 作るもの：CharacterSettings（ScriptableObject）と初期値のアセット
- 値と初期値

| 値 | 初期値 | メモ |
| --- | --- | --- |
| Character Controller の Height | 0.03 | 身長3cm |
| Radius | 0.008 | 太さ1.6cm |
| Center | Y 0.015 | 足元がキャラの原点 |
| Skin Width | 0.0008 | 初期値 0.08 のままだと完全に浮く。必ず変える |
| Step Offset | 0.008 | 自動で登れる段差 0.8cm |
| Slope Limit | 45 | |
| Min Move Distance | 0 | |
| 歩く速さ | 0.15 m/秒 | |
| 重力 | 9.8 m/秒² | 速すぎたら下げる |
| ジャンプの高さ | 0.05 m | 初速は「2×重力×高さ」の平方根で計算する（約 0.99 m/秒） |
| 先行入力 | 0.1秒 | |
| 落ちた直後のジャンプ | 0.1秒 | |
| 落下の速さの上限 | 1 m/秒 | |
| 向きを変える速さ | 720 度/秒 | |
| 跳べる段の上限 | 0.045 m | StepRules の境目 |
| 歩ける段の上限 | 0.008 m | StepRules の境目 |
| カメラの距離 | 初期 0.35、範囲 0.20〜0.80 m | |
| カメラの見下ろす角度 | 初期 40、範囲 20〜80 度 | |

- 確認：アセットがあり、Inspector で値が見える

### Step 3：練習用シーン【CC＋人】

- 目的：AR がなくても PC でキャラを作り込めるようにする
- やること
  1. 【CC】メニュー「DeskStage/C/練習用シーンを作る」で Scenes/Test_C.unity を作るエディタ用スクリプト。中身：幅60cm・奥行き60cm・厚さ1cmの床（上面が高さ0、Terrain）。高さ 0.5、2、4、4.5、5、8cm の箱（幅・奥行き 8cm、Terrain）。2cm と 6cm をくっつけた箱。1cm と 2cm 離して置いた箱の組
  2. 【CC】キャラのプレハブ Gameplay/Prefabs/Player.prefab を作るメニュー：レイヤー Player、Character Controller（値は CharacterSettings）、見た目は子の Capsule（Collider は外す）と、向きが分かる小さな鼻
  3. 【CC】B のお手本ステージ（sample-01）ができたら、それを読み込むボタンも置けるようにする
- 確認：【人】メニューを実行するとシーンとプレハブができる

### Step 4：キャラの移動（CharacterMotor）【CC＋人】

- やること：毎フレーム、次の順で計算し、最後に1回だけ Character Controller を動かす
  1. 入力：DeskStageControls の Move と Jump を読む（D のものがまだなければ同じ名前で仮に作り、できたら入れ替える）
  2. 水平の向きと速さ：向き × 歩く速さ（スティックの倒した量を掛ける）。向きは Step 7 の CameraRelativeInput から受け取る（それまでは世界の前後左右）
  3. 接地：接地していて上下の速さが下向きなら、小さな下向きの値（毎秒 0.05m）に戻す（接地が切れたりついたりしないように）
  4. 最後に接地した時刻と、最後にジャンプが押された時刻を記録する
  5. ジャンプ：押されてから 0.1 秒以内、かつ接地していたのが 0.1 秒以内なら、上下の速さを初速にし、2つの時刻を古い値に戻す
  6. 重力：上下の速さから「重力×経過時間」を引く。落下の速さは上限まで
  7. 動かす：水平と上下の速さを合わせて、経過時間分だけ動かす
  8. 向き：動いているときは進む方向へなめらかに向く
  9. 一時停止中は計算を丸ごと飛ばす
- 確認：【人】PC で WASD とスペースで動き、跳べる

### Step 5：瞬間移動【CC】

- やること：「一度 Character Controller を無効にする → 位置と向きを書き換える → 有効に戻す → 速さをゼロにする」を1つの関数にまとめる。スタートやチェックポイントへ戻すときは、必ずこれを使う
- 確認：【人】練習用シーンで、ボタンを押すと決めた位置に移り、元の場所に戻らない

## M1

### Step 6：視点のカメラ（ViewCamera）【CC＋人】

- 目的：3D画面で、子どもがキャラを見失わない視点を作る
- やること
  1. キャラの少し上（2cm）を見る。距離と見下ろす角度は CharacterSettings の初期値
  2. UiRequests の OrbitView で、横の量はキャラのまわりを水平に回り、縦の量は見下ろす角度を変える（範囲内）
  3. ZoomView で距離を変える（範囲内）
  4. キャラが動くと、なめらかに後を追う
  5. カメラとキャラの間に箱があるときは、カメラをキャラ側に近づける（箱の中に入らない）
  6. 遊び始めは机全体が入る距離から始め、1秒かけてキャラの近くへ寄る（子どもが自分の並べたコース全体を見られるように）
  7. Near Clip Plane を 0.01 にする
- 確認：【人】お手本ステージで、何もしなくてもキャラがいつも画面に入る。指で回して高い箱の裏に回っても、キャラが見える
- 【未決】遊ぶ画面の背景をカメラ映像にすると決まったら、このカメラの代わりにスマホのカメラが視点になる。決まるまでは、このとおり作る

### Step 7：カメラ基準の向き（CameraRelativeInput）【CC＋人】

- やること
  1. カメラの前方向から上下の成分を取り除き、水平な「前」を作る
  2. 真下を向いて「前」の長さが 0.1 未満のときは、カメラの上方向を水平にしたものを「前」にする
  3. 「前」に直角な水平の向きを「右」にし、移動の向き＝「前」×スティックの上下＋「右」×スティックの左右
- 確認：【人】視点をどこに回しても、スティックを上に倒すと画面の奥へ進む。真上から見ても向きが急に変わらない

### Step 8：小さな世界での物理の確かめ【人＋CC】

- やること：【人】練習用シーンで下の表を確かめる。【CC】結果を Docs/StepRules.md に追記する

| 確かめること | 期待 |
| --- | --- |
| 床を30秒歩き回る | 揺れや引っかかりがない |
| 止まって立つ | 浮かず、沈まず、震えない |
| 0.5cm の箱 | 歩いて登れる |
| 2cm、4cm、4.5cm の箱 | ジャンプで登れる |
| 5cm、8cm の箱 | ジャンプでも登れない |
| 2cm から 6cm へ | 足場にして登れる |
| 1cm のすき間 | 落ちずに渡れる |
| 2cm のすき間 | 落ちる（はさまらない） |
| 箱の角を走る | 引っかからない |
| 壁に向かって走り続ける | めり込まない |
| 床の端から出る | 落ちる。出た直後ならジャンプできる |

- 確認：表がすべて期待どおり。違えば CharacterSettings を直し、StepRules の境目と Docs/StepRules.md も直して B と D に知らせる
- 不安定だったときの予備案：物理の計算だけを10倍の大きさの見えない世界で行い、見えるキャラを10分の1の位置に置く。B と D にも影響するので、採用するときは全員で決める

## M3

### Step 11：ゲームの進行（GameFlow）【CC＋人】

- やること：次の状態を持ち、切り替える前に「行けるか」を確かめる（行けないときは無視してログ）

| 今の状態 | きっかけ | 次の状態 | すること |
| --- | --- | --- | --- |
| ステージ待ち | StageBuilt の後、Play | 準備 | キャラを StageRoot の子に作る |
| 準備 | すぐ | プレイ中 | スタートへ瞬間移動、タイムを0にして開始、GameStarted |
| プレイ中 | SetPaused（止める） | 一時停止 | 移動とタイムを止める |
| 一時停止 | SetPaused（再開） | プレイ中 | 再開 |
| プレイ中 | ゴールに触れる | クリア | タイムを止め、記録を保存し、Goal |
| クリア | Retry | 準備 | チェックポイントの通過記録を消す |
| プレイ中・一時停止 | Retry | 準備 | チェックポイントの通過記録を消す（D の一時停止メニューの「もういちど」。2026-10-24 に追加） |
| どの状態でも | BackToList | ステージ待ち | キャラを消す |

- 【未決】遊ぶ画面でカメラ映像を背景に出すと決まったら、スキャン状態が Limited・Lost のときに一時停止する行を足す
- 確認：【人】表のすべての行を実機で起こせる（D の画面がまだなければ、仮のボタンで）

### Step 12：コースの配置（CoursePlacer）【CC＋人】

- 目的：たしかめ画面で、子どもが本物の物を見ながらスタートとゴールを置けるようにする
- やること（PlaceCourseItem を受けたとき）
  1. スマホのカメラ（AR のカメラ）からタップした位置へ光線を飛ばす。相手は Terrain（B の箱と机の板）だけ
  2. 当たらなければ、CoursePlaced で「置けない（机か箱の上ではない）」を返す
  3. 当たった面が上向きでなければ（箱の側面）、「置けない（箱の上ではない）」を返す
  4. 当たった位置を 1mm 上にずらし、ステージ座標に直してステージデータ（spawn、goal、checkpoints）に書く
  5. スタートの向きは、そのときのスマホの水平な向き（置いた子どもから見て奥）
  6. スタートとゴールは1つずつ。もう一度置くと動く。チェックポイントは最大5個。既にあるチェックポイントの 3cm 以内をタップしたら、それを消す
  7. スタートからゴールへ、StepRules で Wall の段を通らないと行けないときも置くのは止めず、CoursePlaced で「とどかないかも」を返す（行けるかの判定は、箱の上面をつないだ簡単な道の探し方から試す。作り方は人に確認する）
  8. 置いた場所に CourseMarkers の目印を出し直す
  9. 保存は B が行う。C はステージデータを書き換えるだけ
- 確認：【人】子どもが説明なしで、本物の物の上にスタートとゴールを置ける。物の側面をタップすると置けないと出る

### Step 13：Game_System プレハブと合流、数値の調整【CC＋人】

- やること
  1. 【CC】メニュー「DeskStage/C/Game_System プレハブを作る」で、GameFlow、ViewCamera、CoursePlacer、SafetyGuard、RecordStore と Player プレハブへの参照をまとめた Gameplay/Prefabs/Game_System.prefab を作るエディタ用スクリプト
  2. 【人】A の宣言のもとで Main に置き、実機で確かめる：スキャンしたステージで、キャラが箱の上を走り、跳んで乗れる。視点を回してもスティックの上で奥へ進む。机の端から落ちると戻る
  3. 【人】歩く速さ、重力、ジャンプの高さを遊びながら調整する（D のデバッグ表示のスライダーで）
  4. 【CC】決めた値と理由を Docs/CharacterParams.md に書き、CharacterSettings の初期値も直す。ジャンプの高さを変えたら StepRules の境目と Docs/StepRules.md も直し、B と D に知らせる
- 確認：Docs/CharacterParams.md に値と理由がある

## M4

### Step 14：スタート・ゴール・チェックポイント（CourseMarkers）【CC＋人】

- やること
  1. spawn、goal、checkpoints の位置に目印を置く（仮の見た目でよい：ゴール＝高さ3cmの旗、チェックポイント＝平らな円盤、スタート＝矢印）。当たり判定は付けない
  2. 触れた判定：毎フレーム、キャラの体の中心と各点の距離を測り、「半径＋キャラの半径」以下なら触れたとする（物理のトリガーは使わない）
  3. チェックポイントに初めて触れたら、最後に通ったチェックポイントを更新し、CheckpointPassed を出す
  4. ゴールに触れたら GameFlow をクリアへ進める
- 確認：【人】チェックポイントとゴールに触れると反応する

### Step 15：落下とはさまりからの復帰（SafetyGuard）【CC＋人】

- やること
  1. 落下：キャラの足元の高さ（StageRoot から見た値）が「0 − fallDepth」より下になったら Fell を出し、最後のチェックポイント（なければスタート）へ瞬間移動する。タイムは止めない。戻った直後 0.5 秒は入力を受け付けない
  2. はさまり：プレイ中に、スティックを倒しているのに3秒間ほとんど動けなければ、最後のチェックポイントへ戻す。起きた場所の近くの箱の id をログに残す（B の直し方の参考）
- 確認：【人】机の端から落ちるとチェックポイントに戻り、タイムが続く。箱のすき間にわざとはさまると3秒後に戻る

### Step 16：タイムと最速記録（RecordStore）【CC＋人】

- やること
  1. 準備からプレイ中になった瞬間に0から数える。一時停止中は数えない（プレイ中のフレームだけ足し上げる）
  2. プレイ中は毎フレーム ElapsedTime を出す
  3. ゴールしたら PlayerPrefs の「best_＋ステージID」と比べ、速ければ更新し、Goal に「最速記録かどうか」を付ける
  4. 並べ直してスキャンしたステージは新しいステージとして保存されるので、記録も新しく始まる
- 確認：【人】下の表がすべて期待どおり

| 確かめること | 期待 |
| --- | --- |
| スタートからゴールまで通す | クリア画面にタイムが出る |
| もう一度遊んで速くゴールする | 最速記録として出る |
| アプリを起動し直す | 最速記録が残っている |
| チェックポイントを通ってから落ちる | チェックポイントに戻り、タイムは続く |
| 一時停止して10秒待つ | タイムが進んでいない |

### Step 17：総点検【人＋CC】

- やること：【人】下の表を確かめる。【CC】結果をまとめ、最終の値を Docs/CharacterParams.md と Docs/StepRules.md に反映する

| 場面 | 確かめること |
| --- | --- |
| 移動 | Step 8 の表を、実機でスキャンしたステージでもう一度 |
| 視点 | 子どもが指で視点を回して、キャラを見失わない |

## 困ったとき

| 起きていること | よくある原因 | 直し方 |
| --- | --- | --- |
| キャラが大きく浮く | Skin Width が 0.08 のまま | 0.0008 にする |
| 立っているだけで震える | 接地中に下向きの速さを加え続けている | Step 4 の3 |
| ジャンプが出たり出なかったり | 接地の判定が切れる | 先行入力と猶予（各 0.1 秒） |
| 箱の角で止まる | 箱の角とキャラの丸み | Step Offset を少し上げる。直らなければ箱の id を B に報告 |
| 箱の継ぎ目で止まる | 上面の高さが数mm違う | B に報告（B がそろえる） |
| 4.5cm に登れない | 重力やジャンプの高さを変えた | 初速を計算し直す。StepRules も直す |
| 視点が箱の中に入る | Step 6 の5 がない | カメラとキャラの間を調べて近づける |
| 戻したのに元の場所にいる | Character Controller を有効のまま動かした | Step 5 の瞬間移動を使う |
| ゴールに触れても反応しない | 世界の位置とステージ座標を混ぜている | どちらかにそろえて測る |
| 一時停止中もタイムが進む | 開始時刻からの差で計算している | プレイ中のフレームだけ足し上げる |
