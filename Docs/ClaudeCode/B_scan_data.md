# B：スキャン・データ Claude Code 作業手順

先に Docs/ClaudeCode/00_overview.md を読んでください。このファイルの名前（クラス、イベント、依頼）は、すべて 00_overview.md の4章の共通コードに合わせています。

## Bの仕事

ステージの「中身」を作って守ります。A が見つけた上面（ScanContext.Surfaces）から、子どもが並べた物に合った箱を作ることが中心の仕事です。読み取りに失敗した所を画面で補う「補助」、stage.json の保存と読み込み、テスト結果のまとめも B の担当です。

完成の姿：子どもが並べた物の上面ごとに、本物と同じ位置・大きさ・高さの箱ができる。並べた物の数と箱の数が合う。並べ直したら、もういちどスキャンで新しい箱にそろう。保存したステージは、起動し直しても同じ形で遊べる。

## ステージの置き場所の決まり

- 同梱用：Assets/StreamingAssets/Stages/。ビルドに含めるステージの原本（お手本ステージ）。iPhone では読むことしかできない
- 保存用：Application.persistentDataPath の Stages/。初回起動時に同梱用からコピーし、以降の読み込みと保存はこちらだけを使う
- iPhone では同梱用のフォルダの中身を一覧できないので、同梱するステージIDの一覧を Stages/index.json に書いて同梱する
- 1つのステージは Stages/<ステージID>/ に、stage.json と表面の画像（任意）を置く

### Step 3：stage.json version 2 の説明と、箱の設定アセット【CC】

取れる値の範囲（読み込み時の確認にも使う）：

| 項目 | 範囲 |
| --- | --- |
| desk の幅・奥行き | 0.2〜3m |
| boxes の数 | 0〜100個 |
| 箱の幅・奥行き | 0.01〜0.6m |
| 箱の高さ | 0.005〜0.4m |

| yawDegrees | 0以上360未満 |
| goal と checkpoints の半径 | 0.01〜0.05m |
| checkpoints の数 | 0〜5個 |

| 値 | 初期値 | 意味 |

| 回転の吸い付け | 15度ごと、5度以内 | 指を離したときに吸い付ける |
| 補助の高さの範囲 | 0.005〜0.40m | |
| 補助の幅・奥行きの範囲 | 0.01〜0.60m | |
| もどすの回数 | 20回 | |
| 机の板の厚さ | 0.01m | 上面が高さ0になるように置く |

- 確認：StageFormat.md と設定アセットがある。C と D が StageFormat.md を読んで分からない項目がない（人）

### Step 5：ステージの組み立て（StageBuilder）【CC＋人】

- 目的：箱の一覧から、キャラが乗れるステージのオブジェクトを作る
- やること
  1. StageRoot の子に、机の板（机の幅・奥行き、厚さ1cm、中心は高さ −0.5cm）と、箱の一覧の1件ごとの直方体を作る
  2. すべてに Box Collider を付け、レイヤーを Terrain にする
  3. 見た目の素材は D の素材を使う。まだなければ単色の仮の素材でよい（D の素材ができたら差し替えられるよう、素材は設定から受け取る）
  4. 箱1つにつきオブジェクト1つ。箱の id で探せるようにし、箱が変わったときはそのオブジェクトだけを直す
  5. 作り終えたら StageContext の StageBuilt を出す
  6. 【CC】メニュー「DeskStage/B/テスト用シーンを作る」で Scenes/Test_B.unity を作り、お手本ステージを読み込んで組み立てるボタンを置く
- 確認：【人】Test_B でお手本ステージを組み立てると、箱が書いたとおりの位置と高さで出る

### Step 6：箱づくり・第1段階（BoxBuilder）【CC＋人】

- 目的：A の上面から、並べた物ごとの箱を作る
- 作るもの：計算の部分（普通のクラス）と、ScanContext を見て動かす部品。EditMode テスト
- やること
  1. SurfacesChanged を受けたら、上面ごとに箱を作る：上から見た形に RectFit（Shared/Geometry、A が作る）を使い、中心・幅・奥行き・回転を求める。箱の高さ＝上面の高さ、中心の高さ＝その半分。source は auto、id は「box-」＋連番
  2. 上面の番号と箱の id の対応を覚える。同じ上面が変わったら同じ箱を直す。上面が消えたら箱も消す
  3. ScanContext.WorkingBoxes を書き換え、BoxesChanged を出す
  4. テスト：四角い上面1つから箱1つ、回した上面から回した箱、上面が変わったら同じ id の箱が変わる、上面が消えたら箱が消える
- 確認：テストが通る。【人】実機でお手本の並べ方をスキャンすると、並べた物の上面ごとに箱が生える（A の部品と合わせて）

## M2

### Step 7：箱づくりの完成【CC＋人】

- 目的：積む、くっつけて並べる、すき間がある、などの並べ方でも本物に合う箱にする
- やること（値は BoxSettings から読む）
  1. 積んだ物：上の物の上面から机までの箱を作る。下の物の上面が一部だけ見えているときは、その部分の箱も作る（重なってよい）
  2. 隣り合う箱の上面の高さの差が 0.008m 未満なら、高い方にそろえる
  3. 箱と箱のすき間が 0.016m 未満なら、片方の箱を広げてすき間をなくす
  4. 高さ 0.005m 未満の上面は箱にしない
  5. 補助で動かした・大きさを変えた・回した箱は source を manual にし、以後は上面が変わっても自動で直さない
  6. FinishScan を受けたら、作業中の箱の一覧を確定する
  7. テスト：高さの差 5mm の2つの箱がそろう、すき間 1cm の2つの箱がくっつく、manual の箱は上面が変わっても変わらない
- 確認：テストが通る。【人】Step 1 の3つの並べ方を再現してスキャンすると、どれも並べた物ごとに箱ができ、積んだ所も本物と同じ高さになる

### Step 8：もういちどスキャン【CC】

- やること
  1. Rescan を受けたら、作業中の箱をすべて消し（manual の箱も）、上面と箱の対応も消す
  2. ステージデータの spawn、goal、checkpoints も消す（置いた物がなくなっている可能性があるため）
  3. BoxesChanged を出す。以後は A の新しい上面から作る
- 確認：【人】物を2つ動かして Rescan すると、動かした後の位置に箱ができ、前の位置の箱が残らない

### Step 9：読み取りの補助（BoxAssist）【CC＋人】

- 目的：見つからなかった物や違う箱を、たしかめ画面で子どもが直せるようにする（補助だけ。ステージは現実の物で作る）
- やること：D の依頼を受けて箱を変える（指の動きの読み取りは D）

| 依頼 | すること |
| --- | --- |
| AddBox（タップ位置） | カメラからタップ先へ光線を飛ばし、Terrain（机の板か箱の上面）に当たったら、一辺5cmの箱を置く。箱の上なら積む。A の検証で「タップした点の高さ」が使えると分かったら、物の上面をタップしたときはその高さを初期値にする |
| SelectBox（タップ位置） | 当たった箱を ScanContext.SelectedBoxId にする。何もない所なら空にする |
| MoveBox（量） | 選んでいる箱を机の面に沿って動かす。机の外に出ない |
| ResizeBox（量） | 幅・奥行きは中心を変えずに変える。高さは底を机に付けたまま上面を上下させる |
| RotateBox（角度） | 上から見た向きだけ回す |
| DeleteBox | 選んでいる箱を消す |
| UndoBox | 1つ前の箱の一覧に戻す |

決まり：補助で足した箱・変えた箱は manual。位置と大きさは 5mm 単位、回転は 15 度ごとの向きに吸い付け、範囲は BoxSettings のとおり。操作の前の箱の一覧全体を「もどす用の記録」に積み、最大20回分残す。テスト：5mm にそろう、範囲で止まる、もどすで元に戻る。
- 確認：テストが通る。【人】たしかめ画面（D がまだなら Test_B の仮のボタン）で、見つからなかった積み木の場所をタップして箱を足し、高さを本物に合わせられる。すべての操作が「もどす」で戻る

### Step 10：ステージ一覧と読み込み（StageCatalog、StageLoader）【CC＋人】

- やること
  1. 初回のコピー：保存用の Stages/ がなければ、index.json を見て同梱用からコピーする。同梱用のステージは、version と更新番号が新しければ上書きする（子どもが作ったステージは同梱用にないので上書きされない）
  2. 一覧：保存用の Stages/ のフォルダを調べ、id、name、createdAt の一覧を新しい順に D へ渡す（渡し方は D と決める。共通コードに足すなら 2.2 のとおり）
  3. SelectStage を受けたら stage.json を読み、中身を確かめる。1つでも当てはまらなければ「読み込めません」とし、理由をログに残す
    - version が2でない（1なら理由は「古い形式」）
    - id がフォルダ名と違う
    - Step 3 の範囲に入っていない
    - 座標の配列の長さが3でない
    - spawn か goal がない
  4. 箱の texture のファイルがないときは、読み込めないにはせず、その箱だけ画像なしにする
  5. 問題がなければ StageContext.CurrentStage に入れて StageLoaded を出し、組み立て（Step 5）を行う
  6. 確かめる部分は普通のクラスにし、EditMode テストを作る（正しいファイル、項目が欠けたファイル、範囲外、version 1、壊れた JSON）
- 確認：テストが通る。【人】実機でお手本ステージが一覧に出て、選ぶと組み立てられる

### Step 11：ステージの保存（StageSaver）【CC＋人】

- やること（SaveStage を受けたとき）
  1. 机の長方形の中心が原点になるように、箱とコースの物の位置をまとめてずらす（A の机の座標は途中で原点を変えないため）
  2. 位置・大きさを 1mm、回転を 0.1 度に丸める
  3. ステージ ID は「stage-」＋日時。表示名は依頼から受け取る
  4. 一時ファイルに書いてから、元の stage.json を stage.json.bak に名前を変え、一時ファイルを stage.json にする（書き込み中にアプリが落ちても壊れない）
  5. 表面の画像があるときは、画像を先に保存する
  6. StageContext の SaveCompleted を出す（成功、または失敗と理由）
- 確認：【人】保存してアプリを終了し、起動し直して一覧から選ぶと、同じ箱とコースで遊べる

### Step 12：読み取りの正しさを測る【人＋CC】

- 目的：子どもが並べたとおりのステージになっているかを数字で確かめる
- やること
  1. 【人】Step 1 の3つの並べ方を再現し、それぞれ3回スキャンする（補助なし）。各箱をデバッグ表示（D）でタップして高さを読み、定規の高さと比べる
  2. 【CC】結果を Docs/ScanAccuracy.md の表にまとめる（並べ方、回、並べた物の数、できた箱の数、足りない箱、余分な箱、高さの差の最大、秒数）
  3. 【CC】足りなかった物を種類ごとにまとめ、A と D に渡す「見つかりにくい物」のメモを書く
- 目標（仮）：補助なしで並べた物の8割以上で箱が合う。高さはすべて±1cm以内
- 確認：表が埋まり、目標との差が書かれている

### Step 13：引っかかり・すり抜けを直す【CC＋人】

- 目的：C からの報告（ステージID・箱の id・起きたこと）を直す
- やること：Docs/StageIssues.md に記録し、下の表で直す

| 報告 | よくある原因 | 直し方 |
| --- | --- | --- |
| 箱と箱の間で引っかかる | 上面の高さが数mm違う | Step 7 の2 が効いているか確かめる |
| すき間に落ちる・はさまる | キャラより細いすき間 | Step 7 の3 が効いているか確かめる |
| 薄い箱をすり抜ける | 高さ 0.5cm 未満の箱 | 補助の箱も含めて下限を守る |
| 本物より箱が小さく端から落ちる | ARKit の面が小さい | A に「ふちを広げる量」の見直しを頼む |
| 積んだ所で跳ねる | 下の物の箱と上の物の箱の高さが近い | 差が 8mm 未満ならそろえる |

- 確認：Docs/StageIssues.md のすべてに「済」が付いている

## M4

### Step 15：読み込めないときの表示と復旧【CC＋人】

- やること
  1. Step 10 で読み込めなかったステージは、一覧に「読み込めません」と理由を付けて渡す（D は選べないように表示する）
  2. stage.json が壊れていて stage.json.bak があれば、そちらを読んで復旧する

## 困ったとき

| 起きていること | よくある原因 | 直し方 |
| --- | --- | --- |
| 並べた物に箱ができない | A の上面が出ていない | デバッグ表示で上面の数を見る。出ていなければ A に相談 |
| 1つの物に箱が2つ | 面のまとめ方、上面の対応のずれ | A に相談。同じ上面は同じ箱を直しているか（Step 6 の2） |
| 箱がちらつく | 箱を毎回作り直している | id で探して直す（Step 5 の4） |
| 補助で直した箱が元に戻る | manual にしていない | Step 7 の5 |
| 並べ直したのに前の箱が残る | Rescan で箱を消していない | Step 8 の1 |
| 保存したのに消えている | 同梱用に書こうとしている、失敗に気づいていない | 保存用の場所に書く。SaveCompleted で失敗を返す |
| 実機で読み込めない | ファイル名の大文字・小文字、index.json に未追加 | ファイル名をそろえる。ログの理由を見る |
| 同梱用を更新したのに古いまま | 保存用に古いコピー | 更新番号を上げる。開発中はアプリを消して入れ直す |
