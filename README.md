## 製品概要

### 背景（製品開発のきっかけ、課題等）

**親の悩み**

「子どもにスマホのゲームばかりさせたくない。でも、取り上げると機嫌が悪くなる」。
未就学児〜小学校低学年の子どもを持つ親の多くが、この板ばさみに悩んでいます。

**根拠**

〈統計を入れる。例：こども家庭庁「青少年のインターネット利用環境実態調査」の、低年齢の子どものインターネット利用時間。出典と年を必ず書く〉

〈チームで聞いた親の声を入れる。例：「〇人中〇人が、ゲームの時間に悩んでいると答えた」〉

**今ある手段がうまくいかない理由**

- 知育アプリ：子どもに「勉強させられている」と見抜かれ、続かない
- 積み木やブロック：楽しいが、親が一緒に遊ばないとすぐ飽きる
- ゲームの時間制限：言い合いになり、親も子どもも疲れる

**きっかけ**

〈チームメンバーの実体験を1〜2文で。例：「弟が積み木で作ったコースに、ゲームのキャラを走らせたいと言ったこと」〉

**私たちが立てた問い**

親が本当に求めているのは、子どもが自分から夢中になって遊び、その結果として考える力が自然に育つことです。
子どもが大好きな「ゲーム」を入り口にして、手を動かす現実の遊びへ連れ出せないか。これが出発点です。

### 製品説明（具体的な製品の説明）

子どもが机の上に、段ボール箱・積み木・本など**家にある物**を並べてコースを作ります。
iPhone で机を2枚撮るだけで、並べた物の形がそのまま3Dのステージになり、身長3cmのキャラクターで遊べます。

**遊び方**

| 1. ならべる | 2. とる | 3. たしかめる | 4. あそぶ |
| --- | --- | --- | --- |
| ![](Docs/images/step1_place.png) | ![](Docs/images/step2_shoot.png) | ![](Docs/images/step3_check.png) | ![](Docs/images/step4_play.png) |
| 机に物を並べる。紙の「たかさものさし」で、跳べる高さを確かめられる | 真上と斜めから2枚撮る | 並べた物が箱になって出てくる。本物の物を見ながら、スタートとゴールを置く | キャラを動かしてゴールを目指す。タイムと最速記録が残る |

〈画像：実際のアプリの画面写真を Docs/images/ に置く。クリア画面と、たかさものさしの写真もあるとよい〉

うまく登れない段があれば、子どもは「となりに本を置いて階段にしよう」と自分で並べ直し、撮り直して挑戦します。
この **並べる → 遊ぶ → 並べ直す** の繰り返しが、このアプリの中心です。

**親にとって**

- 用意するのは、家にある物と iPhone だけ。特別なおもちゃを買い足す必要がない
- 親が付きっきりで教えなくても、子どもが自分で遊び方を見つける

### 既存のサービスとの違い（差別化）

〈各サービスの説明は、提出前に公式サイトで確かめて直す〉

| | 現実の物を使う | 専用の部品が要らない | 立体（高さ）がゲームのルールになる | 何度でも作り直せる |
| --- | --- | --- | --- | --- |
| **つくえのうえステージ** | ○ 家にある物なら何でも | ○ | ○ 4.5cm まで跳べる | ○ 並べ直して撮るだけ |
| 紙やブロックの絵を撮ってゲームにする系（例：Bloxels） | ○ | × 専用のボードとブロック | × 平面（2D） | ○ |
| カメラで手元の部品を読む知育（例：Osmo） | ○ | × 専用の部品 | △ | △ 決まった課題 |
| 段ボール工作とゲーム機（例：Nintendo Labo） | ○ | × 専用キット | × | △ |
| ゲームの中で作る（例：Minecraft） | × 画面の中だけ | ○ | ○ | ○ |

**ここだけの点**

- **家の物そのものがステージになる**：専用キットを買わずに始められる
- **現実の高さが、そのままゲームのルールになる**：「4.5cm までは跳べる、それより上は壁」。現実の物差し（[たかさものさし](Docs/HeightGauge.md)）で確かめられ、遊びと学びがつながる

### 解決できること

- **親**：画面の中だけで終わらない遊びを、無理なく子どもに渡せる。ゲームを取り上げる言い合いが減る
- **子ども**：「勉強」と感じずに、ただ楽しく遊べる。ゴールに着きたくて、自分から何度も工夫する
- **気づいたら身についている力**
  - 高さや長さの感覚（何cm なら跳べるか）
  - 順番を考える力（低い物から階段にする）
  - 試して、うまくいかなければ直す力
  - 手先を使って物を積む・並べる力

### このアプリでないと解決できないこと

- **ゲームの「やりたい」気持ちを、現実の物を並べる行動に変える**のは、現実の物がそのままステージになる仕組みがあって初めてできます。ゲームだけ、積み木だけでは起きません
- **高さの感覚を、遊びの中で体で覚える**のは、ゲームの段の決まり（4.5cm）と、現実の物差しを同じ値にそろえたからできます
- **家にある物だけで始められる**ので、専用のおもちゃを買う負担がなく、どの家庭でもすぐ試せます

### 今後の展望

**すぐに広げられる理由**

- 必要なのはスマホと家の物だけ。特別な機器や専用キットが要らない
- 読み取りは写真2枚とサーバーだけで行い、AR（ARKit）を使わないため、iPhone 以外（Android、タブレット）にも広げやすい（Unity で作っているため）
- API キーはサーバーにだけ置き、写真は保存しない。親が安心して使える

**費用と台数の見通し**

- 読み取り1回あたりの API の料金：〈サーバーのログに残るトークン数から計算して書く〉
- 1日の読み取り回数に上限を設けて、費用が膨らまないようにしている（今は1日100回）
- 〈利用者が増えたときのサーバーの増やし方。例：サーバーを複数台にする、混む時間は待ち行列にする〉

**お金の流れの案**

- 〈例：アプリは無料、1日〇回まで読み取り無料。たくさん遊ぶ家庭は月額〇円〉
- 〈例：保育園・学童・図書館などでの、まとめての利用〉

**作りたい機能**

- 色や形で決まるギミック（色の箱に乗ると何かが起きる、など。今は予約だけしてある）
- 作ったステージを家族や友だちと共有して、タイムを競う
- 子どもテストの結果をもとに、読み取りの正確さを上げる

### 注力したこと（こだわり、自信があるところ）

* **現実の高さとゲームの高さを一致させた**
  身長3cm の小さなキャラの物理は、ふつうのゲームの設定では引っかかったり浮いたりします。自動テストで段・すき間・角を1つずつ測り、ジャンプ 5cm のときは 5.5cm の箱まで乗れてしまうことを見つけて、4cm に直しました。その結果、「4.5cm まで乗れて、4.75cm からは乗れない」をテストで確かめています
* **子どもが説明なしで、つまずかずに遊べる**
  カメラはキャラを見失わないように自動で追い、箱の裏に回るとカメラが上がって見えるようにしました。落ちても最後に踏んだチェックポイントに戻ります。ゴールまで行けないコースは「？」で知らせ、置けないときは理由を短く伝えます
* **親が安心して渡せる**
  文字はひらがな中心。写真はサーバーに保存せず、API キーはアプリに入れません
* 〈A・B・D の担当が、それぞれのこだわりを足す〉

## 開発技術

### 活用した技術

#### API・データ

* Claude API（モデル `claude-opus-5-5`、構造化出力）：机の写真2枚から、物ごとの位置・大きさ・高さを決まった形の JSON で読み取る

#### フレームワーク・ライブラリ・モジュール

* Unity 6（6000.6.6f1）、Universal Render Pipeline、Input System、Unity Test Framework
* Python、FastAPI、uvicorn、Anthropic Python SDK（読み取りサーバー）

#### デバイス

* iPhone（撮影と遊ぶ画面）

### 独自技術

#### ハッカソンで開発した独自機能・技術

* **写真から箱の地形を作る仕組み**：Claude の答え（物ごとの中心・大きさ・回転）を、机の中心を原点にした箱の一覧に直し、すき間や高さのずれを整えて、キャラが乗れる地形にする
* **小さな世界の物理の実測**：身長3cm のキャラが箱の上を引っかからずに動けるよう、自動テストで段の高さ・すき間・角・壁を確かめ、ジャンプの高さと「跳べる段の上限」を実測で決めた
* **ゴールまで行けるかの判定**：机と箱の上面を「場所」とし、上りは 4.5cm まで・下りは自由として道をたどる。行けないコースは置く時点で知らせる
* **子どもが見失わないカメラ**：キャラを追い、箱の裏に回るとカメラを持ち上げて上から見る

#### 特に力を入れた部分（ファイルとコミット）

* キャラの物理の実測：[SmallWorldPhysicsTests.cs](Assets/_Project/Gameplay/Tests/PlayMode/SmallWorldPhysicsTests.cs)、ジャンプを 5cm → 4cm に直したコミット `7d24b9c`
* ゴールまで行けるかの判定：[CourseReachability.cs](Assets/_Project/Gameplay/CourseReachability.cs)、コミット `c7d92ff`
* 子どもが見失わないカメラ：[ViewCamera.cs](Assets/_Project/Gameplay/ViewCamera.cs)
