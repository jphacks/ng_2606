## 製品概要

### 背景（製品開発のきっかけ、課題等）

**画面ばかりの家の時間を、手を動かす時間に**

子どもには外で体を動かして遊んでほしい、と願う親は多くいます。
でも今の子どもたちは、家にいる間、スマホやタブレットを触ってばかりです。0〜9歳の子どもでも、インターネットを使う時間は平日1日あたり平均で約2時間18分。しかも、年々長くなっています[^1]。

だったら、画面を取り上げるのではなく、**画面の時間そのものを、手を動かす遊びに変えてしまおう！**
「ならべて！ステージ」は、スマホの中だけで終わっていた遊びと、外で体を動かす遊びをつなぐ、最初の一歩になるアプリです。

**想定する利用者**

- **子ども**：未就学から小学生まで。積み木・箱・人形で、街や冒険を作って遊ぶのが好き。画面の言葉はひらがな中心で、読めない子は、親が読んであげれば遊べる
- **親**：子どもに、ただ見るだけでなく、**自分で作る遊び**をさせたい。休日や夕方に、家にある物で、親子で一緒に遊びたい
- **遊ぶ場面**：親子で一緒に遊ぶのが中心。親の iPhone を借りて子どもが1人で遊ぶ、きょうだいや友だちとタイムを競う、という使い方も想定している

**作った世界は、想像の中でしか動かない**

子どもは、積み木や箱で街を作り、人形を手に持って冒険させて遊びます。メンバーの1人も、小さいころ、車の窓に指人形を立てて、流れる建物を飛び越えさせていました。
でも、人形を動かすのは自分の手なので、どんな高さも飛び越えられます。作った世界は、想像の中でしか動きません。

**ゲームの世界は本当に動く。でも、自分で作ったものではない**

ゲームでは、キャラが自分の足で走り、高すぎる所には登れません。世界が、ルールどおりに動きます。
でも、その世界は、ゲームを作った人が用意したもので、子どもが自分の手で作ったものではありません。

**作った世界を、そのままゲームに**

| | 世界を作る人 | 世界の動き方 |
| --- | --- | --- |
| 積み木・人形遊び | 自分 | 想像の中だけ（自分の手で動かす） |
| ゲーム | ゲームを作った人 | 本当に動く（ルールがある） |
| **ならべて！ステージ** | **自分** | **本当に動く（高さがルール）** |

机の上に作った世界が、そのままゲームの世界になれば、「作る遊び」と「動かす遊び」を1つにできます。
キャラは、並べた箱の上を走り、高すぎる所には登れません。子どもは、本を足して階段にするなど、手で並べ方を変えて先に進みます。

### 製品説明（具体的な製品の説明）

未就学から小学生までの子どもと親が、机の上に、段ボール箱・積み木・本など**家にある物**を並べてコースを作ります。
iPhone で机を2枚撮るだけで、並べた物の形がそのまま3Dのステージになり、身長3cmのキャラクターで遊べます。
撮った写真は AI が読み取り、物の位置・大きさ・高さを割り出して、キャラが乗れる箱の形にします。写真は、読み取りサーバーを通して外部の AI サービス（Claude API）に送り、形の読み取りにだけ使います。サーバーは、写真を保存せず、ログにも書きません。

#### 子ども向けの言葉

撮る・待つ・たしかめる・あそぶ、すべての工程で、ひらがな中心の短い言葉を使っています（「まうえから とってね」「ステージを つくっているよ」「うまく いかなかったよ」など）。うまくいかなかったときの案内も、子どもが読める言葉です。ボタンは、子どもが指で押しやすい大きさにしています。

#### 自分だけのキャラクター

| キャラを えらぶ | 写真を撮って キャラにする |
| --- | --- |
| <img src="Docs/images/screen_character_select.png" width="400" alt="キャラを えらぶ"> | <img src="Docs/images/screen_character_shoot.png" width="400" alt="写真を撮ってキャラにする"> |

遊ぶキャラクターは、最初から用意された「いつもの こ」のほかに、写真を撮って自分だけのキャラクターを作れます。キャラクターの写真は、端末の中だけに保存し、外には送りません。
画面に出る人形の形の枠に合わせて、頭から足まで入るように撮るだけです。自分や家族、お気に入りのぬいぐるみが、自分で作ったステージを走り回ります。

#### ステージの背景

<img src="Docs/images/screen_background.png" width="640" alt="ステージの はいけい">

ステージの背景は、「あおぞら」「ゆうやけ」「もり」「うみ」「ほしぞら」「おへや」から選べます。写真を撮って、好きな景色を背景にすることもできます。背景の写真も、端末の中だけに保存し、外には送りません。

#### 遊び方

**1. ステージをえらぶ**

<img src="Docs/images/screen_stage_list.png" width="640" alt="ステージ いちらん">

「あたらしく つくる」を押すと、机の上の物を撮って新しいステージを作ります。前に作ったステージや、最初から入っている「おてほん」を選んで、すぐに遊ぶこともできます。
キャラクターと背景は、この画面の上の「キャラ」と「はいけい」から選びます。

**2. 机に物を並べて、2枚撮る**

| まうえから | ななめから |
| --- | --- |
| <img src="Docs/images/screen_shoot_top.png" width="400" alt="真上から撮る"> | <img src="Docs/images/screen_shoot_diagonal.png" width="400" alt="斜めから撮る"> |

机の上に、箱・積み木・本などを並べてコースを作ります。子どもが並べて、親子で撮ります。
撮る前の画面で、写真を送ることを子ども向けの言葉で伝え、おうちの人といっしょに見るようにすすめています。
画面の案内に合わせて、まず真上から、次に斜めから撮ります。真上の写真で物の位置と大きさを、斜めの写真で物の高さを読み取ります。

キャラは小さな人形で、2段ジャンプで、ペットボトルくらいの高さ（約20cm）までなら乗れます。それより高い所には、低い物を足して階段にしないと登れません。並べるときから、「どうすれば登れるか」を考えるのが遊びの始まりです。

**3. ステージができるのを待つ**

<img src="Docs/images/screen_building.png" width="640" alt="ステージを つくっているよ">

撮った写真から、数十秒でステージができあがります。待っている間は、さっき撮った写真と、あと何秒かが表示されます。

**4. スタートとゴールを置いて、あそぶ**

| ほんものと おなじかな？ | あそぶ |
| --- | --- |
| <img src="Docs/images/screen_check.png" width="400" alt="ほんものと おなじかな？"> | <img src="Docs/images/screen_play.png" width="400" alt="あそぶ画面"> |

並べた物が、そのままの形の箱になって画面に出てきます。実機で試した範囲では、物の大きさや高さが、本物にかなり近いまま、リアルなステージになります。箱の上面には、撮った写真を貼るので、見た目も本物そっくりです。「ほんものと おなじかな？」の画面で、本物の物と見比べて確かめます。形がちがう所があれば、本物の物を並べ直して「もういちど とる」で撮り直すのが、いちばんの直し方です。小さなずれなら、画面の上の「なおす」でも直せます。
ジャンプで乗れる所には「とぶ」の印が出て、高すぎて届かない所には、ひくい物をとなりに置くよう案内が出ます。
机や箱の上をタップして、スタートとゴールを置きます。「ほぞん」を押すと、ステージ一覧に残ります（一覧の絵は、1枚目の写真を小さくしたもので、端末の中だけに残ります）。

「あそぶ」を押すと、ゲームが始まります。左下のスティックでキャラを動かし、右下の「ジャンプ」で跳んで、ゴールを目指します。ジャンプは、跳んでいる間にもう一度押して、2段階ジャンプまでできます。
画面の上には、ゴールまでのタイムと、キャラの体力（HP）を表すハートが出ます。

並べた物の色によって、箱の上で起きることが変わります。

| 箱の色 | 起きること |
| --- | --- |
| 赤 | 炎が出ていて、乗るとダメージを受け、ハートが減る |
| 青 | 水が流れていて、乗るとキャラが流される |
| 緑 | 乗ると回復して、ハートが増える |

箱の上面の85%以上が、同じ色のときだけ、その色のしかけになります（少し色が入っているだけでは、しかけになりません）。色は、色相・彩度・明るさで見分けています。

どの色の物をどこに置くかで、やさしいコースにも、むずかしいコースにもなります。
ゴールまでのタイムは記録され、そのステージの最速記録も残るので、何度でも挑戦したくなります。

**5. もう一度並べなおす**

<img src="Docs/images/screen_rearrange.png" width="640" alt="もう一度並べなおす">

うまく登れない段があれば、子どもは「となりに本を置いて階段にしよう」と自分で並べ直し、撮り直して挑戦します。
この繰り返しが、このアプリの中心です。

### 解決できること

- **親**：子どもが、ただ見るだけでなく、**自分で考えて作る**遊びを、見守りながら、一緒に楽しめることを期待しています
- **親子**：「この箱は高すぎるかな？」「本を置いたら登れたね」と、コース作りをきっかけに、自然に会話が生まれることを期待しています。親がゲームの外から一緒に参加できます
- **子ども（未就学〜小学生）**：ひらがなの短い言葉だけで、自分で並べて撮って遊べます。勉強と感じずに、ただ楽しく遊べます。自分で並べた物がステージになるので、自分の作品として夢中になれると考えています

**身に付くことを期待している力**

- **試行錯誤する力**：うまくいかなければ、並べ方を変えてもう一度試す
- **空間認識能力**：物の高さ・大きさ・位置の関係をつかむ
- **計画を立てる力**：低い物から順に置いて階段にするなど、道筋を先に考える
- **手先の器用さ**：物を積む・並べる

### 今後の展望

**実現に向けて**

- **必要なのは iPhone と家の物だけ**です。特別な機器や専用キットは要りません
- いまは iPhone だけで動かしています。Unity で作っているので、ほかの端末への展開も今後検討します（まだ試していません）

**将来の方向：端末の中だけで完結させる**

いまは、撮った写真を AI に送って、物の形を読み取っています。将来は、iPhone の AR（平らな面や距離の検出）などで形を読み取り、AI もサーバーも使わない形にしたいと考えています。そうなると、

- 写真が端末内に収まる
- 通信がなくても遊べる

ようになり、より多くの家庭で、安心して使えるようになります。

| 作りたい機能 | なぜ作りたいか | 実現できる根拠 |
| --- | --- | --- |
| 作ったステージを家族や友だちと共有して、タイムを競う | 自分の作品を見せたい、だれかに遊んでほしいという気持ちが、次のコース作りの原動力になる | ステージは小さなデータ（stage.json）1つで表せる。今の読み取りサーバーに、保存と受け渡しを足せば送れる |
| 読み取りの正確さを上げる | 並べた物と画面の箱がずれると、楽しさが減ってしまう | 読み取りの答えには、物ごとに「どれくらい自信があるか」が入っている。A4 の紙を一緒に写すと長さが正確になる仕組みもあり、指示文の調整で改善できる |
| 色のしかけを増やす（例：踏むと高く跳べるジャンプ台、すべる床、ワープ） | しかけが増えるほど、「どの色をどこに置くか」を考える遊びが広がり、コース作りの工夫が増える | しかけは、箱ごとの1つの項目で決まり、色の判定と効き目の部分が分かれている。新しい色と効き目を足すだけで、増やせる |

### 注力したこと（こだわり、自信があるところ）

3D スキャンのアプリや、AI で 3D モデルを作るツール、段ボールの工作キットはありますが、**家にある物の高さを、そのままゲームのルールにする**ものではありません。

* **現実の物の高さを、そのままゲームの足場にした**
  並べた物の高さが、そのままゲームのルールになります。家にある物なら何でもステージになり（専用の部品は要りません）、高すぎる所には登れないので、並べ直して撮り直すことが、遊びの中心になります。
* **身長3cm の世界で、ちゃんと遊べる物理にした**
  ふつうのゲームの設定では、3cm のキャラは、引っかかったり浮いたりします。自動テストで段・すき間・角を1つずつ測り、ジャンプの高さと「乗れる段の上限」を実測で決めました。キャラの丸い足元のおかげで、ジャンプの高さより約0.5cm 高い箱まで乗れます（12cm のジャンプで 12.5cm）。2段ジャンプでは、実測で 24cm の箱まで乗れたので、決まりの上限は、余裕をみて 22cm にしています。ゴールまで行けないコースは、置く時点で知らせます。
* **机の写真2枚から、乗れる地形を作る**
  真上と斜めの2枚の写真から、AI が物の位置・大きさ・高さを読み取ります。答えの形を決めた形式（構造化出力）にして、読み取った箱の高さやすき間をそろえ、キャラが乗れる3Dの地形にします。撮った写真は箱の上面に貼って、見た目も本物に近づけます。
* **直し方の主役は、現実の物を並べ直して撮り直すこと**
  形がちがうときは、画面の上で直すより、本物を並べ直して「もういちど とる」のが、いちばんの直し方です（画面の上の「なおす」は、小さなずれ用）。「並べる→遊ぶ→並べ直す」の繰り返しが、このアプリの中心です。
* **未就学から小学生までが、説明なしでつまずかずに遊べる**
  すべての工程で、ひらがな中心の短い言葉と、押しやすい大きなボタンを使い、うまくいかなかったときの案内も、子どもが読める言葉にしました。カメラはキャラを見失わないように自動で追い、箱の裏に回ると上がって見えます。落ちても、最後に踏んだチェックポイントに戻ります。
* **色で変わる、折り紙のしかけ**
  箱の上面が、一面、青・赤・緑の折り紙なら、水（流される）・炎（ハートが減る）・回復になります。色は、色相・彩度・明るさで見分け、実機で撮った折り紙の色で、判定の範囲を決めました。少し色が入っているだけでは、しかけになりません。

## 開発技術

### 活用した技術

#### API・データ

* Claude API（モデル `claude-opus-5-5`、構造化出力）：机の写真2枚から、物ごとの位置・大きさ・高さを、決まった形の JSON で読み取る。答えの形を決めてあるので、アプリがそのまま箱の一覧に直せる

#### フレームワーク・ライブラリ・モジュール

| 技術 | 使う場面 |
| --- | --- |
| Unity 6（6000.6.6f1）、Universal Render Pipeline | アプリ全体。3D のステージ、画面、ゲーム |
| C#、UGUI、TextMeshPro | 12 枚の画面を、コードで作る。ひらがな中心の日本語の表示 |
| Input System | 画面のスティックとジャンプボタン |
| WebCamTexture | 撮影。カメラ映像、向きの補正、暗い・ぶれた写真の判定 |
| UnityWebRequest | 撮った写真 2 枚を、読み取りサーバーに送る |
| Python、FastAPI、uvicorn、Anthropic Python SDK | 読み取りサーバー。写真を受け取り、AI に聞いて、答えを返す |
| CharacterController | 身長 3cm のキャラの動き、2段ジャンプ、しかけで流される動き |
| Unity Test Framework | 計算の自動テストと、箱に乗れる高さの実測 |
| Xcode、devicectl | iPhone へのビルドと、実機での確認 |

#### デバイス

* iPhone：撮影と、遊ぶ画面
* Mac：読み取りサーバーの実行と、Unity のビルド（開発用）

### 独自技術

#### ハッカソンで開発した独自機能・技術

特に力を入れた部分は、ファイルへのリンクを、それぞれの項目に付けています。

* **写真から箱の地形を作る仕組み**：Claude の答え（物ごとの中心・大きさ・回転）を、机の中心を原点にした箱の一覧に直し、すき間や高さのずれを整えて、キャラが乗れる地形にする
  * 読み取りサーバー：[Server/app.py](Server/app.py)、Claude への指示文 [scan_prompt.md](Assets/_Project/Stage/Llm/scan_prompt.md)
  * 答えを箱の一覧に直す：[StageReaderCore.cs](Assets/_Project/Stage/StageReaderCore.cs)
* **小さな世界の物理の実測**：身長3cm のキャラが箱の上を引っかからずに動けるよう、自動テストで段の高さ・すき間・角・壁を確かめ、ジャンプの高さと「跳べる段の上限」を実測で決めた（1回のジャンプで 12.5cm、2段ジャンプで 24cm の箱まで乗れる）
  * [SmallWorldPhysicsTests.cs](Assets/_Project/Gameplay/Tests/PlayMode/SmallWorldPhysicsTests.cs)
* **ゴールまで行けるかの判定**：机と箱の上面を「場所」とし、上りは 22cm まで（2段ジャンプ）・下りは自由として道をたどる。行けないコースは置く時点で知らせる
  * [CourseReachability.cs](Assets/_Project/Gameplay/CourseReachability.cs)、コミット `c7d92ff`
* **子どもが見失わないカメラ**：キャラを追い、箱の裏に回るとカメラを持ち上げて上から見る
  * [ViewCamera.cs](Assets/_Project/Gameplay/ViewCamera.cs)
